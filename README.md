## چکیده

پروژهٔ **تترا شاپ** یک سکوی نرم‌افزاری سبک، بدون حالت (stateless) و مبتنی بر معماری RESTful است که سه خدمت اصلی را در یک اکوسیستم واحد گرد هم می‌آورد: **تبدیل تصاویر دوبعدی به مدل‌های سه‌بعدی**، **تشخیص نوری کاراکترها (OCR)** و **تولید خودکار محتوای متنی**. این سیستم با زبان JavaScript/Node.js و چارچوب Express پیاده‌سازی شده و با هدف ارائهٔ یک API پایدار، ایمن و قابل اجرا در محیط‌های محدود (مانند Termux روی اندروید) طراحی گردیده است. در مسیر توسعه، چالش‌های متعددی از جمله ناسازگاری کتابخانه‌های باینری، محدودیت دسترسی به اینترنت و ضعف‌های امنیتی شناسایی و رفع شد. نسخهٔ نهایی علاوه بر قابلیت استقرار محلی، برای اجرا روی سرویس‌های ابری مانند Vercel نیز بهینه‌سازی شده است. این مقاله به تشریح معماری، جزئیات فنی، مشکلات پیش‌آمده و راه‌حل‌های به‌کاررفته می‌پردازد.

**کلیدواژه‌ها:** Node.js، Express، OCR، تبدیل ۲D به ۳D، تولید متن، JWT، SQLite، Jimp، Tesseract.js، Ocrad.js، Termux، Vercel

## ۱. مقدمه

امروزه ابزارهای مبتنی بر هوش مصنوعی و پردازش تصویر جایگاه ویژه‌ای در اتوماسیون کسب‌وکارها دارند. بسیاری از سکوهای فروشگاهی، تولیدکنندگان محتوا و توسعه‌دهندگان به APIهایی نیاز دارند که بتوانند بدون وابستگی به سخت‌افزار خاص، خدماتی مانند تبدیل تصویر محصول به مدل سه‌بعدی، استخراج خودکار متن از اسناد تصویری و نگارش توضیحات تبلیغاتی را ارائه دهند. تترا شاپ در پاسخ به این نیازها متولد شد: **یک API یکپارچه، با حداقل وابستگی، قابل اجرا روی موبایل (از طریق Termux) و قابل ارتقا به مدل‌های زبانی پیشرفته**.

هدف اولیهٔ پروژه، ایجاد یک نمونهٔ اولیه (MVP) بود که بتواند مفاهیم "اکوسیستم کوانتومی" را شبیه‌سازی کند. اما پس از شناسایی ضعف‌های امنیتی و عملکردی، مسیر توسعه به سمت پیاده‌سازی واقعی ویژگی‌ها تغییر یافت. در این مستند، روند تکامل پروژه گام‌به‌گام شرح داده می‌شود.

## ۲. معماری سیستم

سیستم تترا شاپ بر پایهٔ **الگوی MVC ساده‌شده** بنا شده است. هر جزء اصلی در یک ماژول جداگانه قرار دارد:

- **server.js**: هستهٔ سرور Express، تعریف مسیرها (routes)، میدلورهای عمومی و مدیریت خطا.
- **converter.js**: سرویس تبدیل تصویر دوبعدی به مدل سه‌بعدی (OBJ/STL) با استفاده از Jimp و الگوریتم displacement mapping.
- **ocr.js**: سرویس تشخیص متن (OCR) با دو موتور: **Tesseract.js** (برای محیط‌های آنلاین) و **Ocrad.js** (برای محیط‌های آفلاین).
- **writer.js**: موتور تولید محتوای متنی مبتنی بر قالب‌های از پیش تعریف‌شده و امکان اتصال به APIهای خارجی (Hugging Face).
- **auth.js**: مدیریت احراز هویت با توکن‌های JWT.
- **database.js**: لایهٔ ذخیره‌سازی کاربران با استفاده از SQL.js (SQLite درون‌حافظه).
- **public/**: فایل‌های استاتیک شامل یک پنل کاربری تک‌صفحه‌ای (SPA) که با HTML خالص و JavaScript پیاده‌سازی شده است.

### نمودار جریان درخواست

```

[کلاینت] --> [Express Server] --> [مسیریاب]

```

پایگاه دادهٔ کاربران نیز از طریق `database.js` در یک فایل `tetra.db` ذخیره می‌شود که با کمک `sql.js` مدیریت می‌گردد و برای محیط‌های بدون فایل‌سیستم پایدار (مانند Vercel) به صورت درون‌حافظه‌ای عمل می‌کند.

## ۴. جزئیات خدمات

### ۴.۱ تبدیل ۲D به ۳D

**مسیر:** `POST /api/convert-3d`  
**ورودی:** تصویر به صورت رشتهٔ base64 (فرمت‌های PNG/JPEG)، پارامترهای `format` (obj یا stl) و `useEdge` (true/false).  
**پردازش:**  
1. تصویر با کتابخانهٔ Jimp به عرض حداکثر ۲۵۶ پیکسل تغییر اندازه می‌دهد.  
2. در صورت فعال بودن `useEdge`، یک فیلتر سادهٔ Sobel برای تشخیص لبه اعمال می‌شود.  
3. هر پیکسل به یک vertex با ارتفاع متناسب با روشنایی آن پیکسل تبدیل می‌گردد (displacement mapping).  
4. فیس‌ها (مثلث‌ها) بین vertexها تشکیل می‌شود.  
5. خروجی به صورت رشتهٔ OBJ یا STL تولید و در یک کش موقت ذخیره می‌شود.  
6. یک `modelId` یکتا تولید و به کلاینت برگردانده می‌شود تا از طریق `GET /api/download?model=...` دریافت گردد.

**خروجی نمونه (OBJ):**
```

مدل سه‌بعدی تترا شاپ

o TetraModel
v -2.500000 0.000000 -2.500000
v -2.480315 0.023529 -2.500000
...
f 1 2 258
f 2 258 259
...

```

### ۴.۲ سرویس OCR

**مسیر:** `POST /api/ocr`  
**ورودی:** تصویر به صورت base64 و پارامتر اختیاری `lang` (پیش‌فرض: eng).  
**راهکار نهایی (دوگانه):**  
- **موتور اصلی (Tesseract.js):** در محیط‌هایی که اینترنت در دسترس است، فایل‌های traineddata را از سرورهای رسمی دانلود کرده و OCR با دقت بالا انجام می‌دهد.  
- **موتور fallback (Ocrad.js):** در صورت بروز هرگونه خطا (مانند `ENOTFOUND` یا عدم دسترسی به شبکه)، سیستم به‌طور خودکار از OCR آفلاین استفاده می‌کند. این موتور با کمک Jimp تصویر را بهینه‌سازی کرده و با `pngjs` یک آبجکت PNG مناسب می‌سازد، سپس آن را به Ocrad.js تحویل می‌دهد.  
**مدیریت خطا:** هر دو مسیر در یک بلاک `try/catch` قرار دارند؛ در صورت شکست کامل، پاسخ ۵۰۰ با پیام مناسب برگردانده می‌شود و سرور پایدار می‌ماند.

**چرایی این طراحی:**  
توسعهٔ اولیه روی محیط Termux (اندروید) انجام شد. تلاش برای نصب Tesseract باینری (`pkg install tesseract`) به دلیل محدودیت کلیدهای مخزن ناموفق بود. نصب بسته‌های npm مانند `tesserocr` نیز با خطای ۴۰۴ مواجه شد. استفاده از `tesseract.js` با مشکل دانلود traineddata (ENOTFOUND) مواجه گردید. در نهایت، ترکیب `tesseract.js` به‌عنوان گزینهٔ اصلی و `ocrad.js` به‌عنوان پشتیبان، پایداری را در تمام محیط‌ها تضمین کرد.

### ۴.۳ نویسنده هوشمند

**مسیر:** `POST /api/writer`  
**ورودی:** `type` (product | blog | social) و `params` (شامل product, price, feature1, ...).  
**عملکرد:**  
- مجموعه‌ای از قالب‌های از پیش تعریف‌شده به زبان فارسی برای تولید توضیحات محصول، پست‌های وبلاگ و محتوای شبکه‌های اجتماعی.  
- در صورت تنظیم `HF_TOKEN` (توکن Hugging Face)، سیستم ابتدا تلاش می‌کند از مدل `zephyr-7b-beta` برای تولید متن استفاده کند؛ در غیر این‌صورت، خروجی مبتنی بر قالب را برمی‌گرداند.  
- این طراحی امکان ارتقای آسان به مدل‌های پیشرفته‌تر را فراهم می‌کند.

### ۴.۴ احراز هویت و مدیریت کاربران

**مسیرها:**  
- `POST /api/users/register` – ثبت‌نام با رمز عبور هش‌شده (bcrypt).  
- `POST /api/users/login` – ورود و دریافت توکن JWT.  
- `GET /api/users/me` – دریافت اطلاعات کاربر احراز هویت‌شده (نیازمند توکن).  

**امنیت:**  
- رمزهای عبور با bcryptjs و salt ۱۰ دور هش می‌شوند.  
- توکن‌های JWT با کلید مخفی (قابل تنظیم از متغیر محیطی `JWT_SECRET`) امضا می‌شوند و تاریخ انقضای ۷ روزه دارند.  
- میدلور `authMiddleware` از دسترسی‌های غیرمجاز جلوگیری می‌کند.  

**ذخیره‌سازی:**  
پایگاه داده با `sql.js` در فایل `tetra.db` ذخیره می‌شود. برای استقرار روی Vercel (که فایل‌سیستم write محدودی دارد)، می‌توان پایگاه داده را به‌صورت درون‌حافظه‌ای نگه داشت یا به یک سرویس خارجی متصل کرد.

## ۵. چالش‌ها و راه‌حل‌های اعمال‌شده

در طول توسعه، خطاهای متعددی ظاهر شد که هر یک درسی ارزشمند برای طراحی سیستم‌های مقاوم به همراه داشت. جدول زیر مهم‌ترین چالش‌ها و پاسخ‌ها را خلاصه می‌کند:

| ردیف | خطا / مشکل | علت | راه‌حل نهایی |
|------|------------|-----|---------------|
| ۱ | `SyntaxError: Unexpected token '*'` در `converter.js` | استفاده از دستور `import * as THREE` در ماژول CommonJS | حذف خط غیرضروری (نیازی به Three.js نبود) |
| ۲ | `ReferenceError: express is not defined` | فراموشی `require('express')` در ابتدای `server.js` | افزودن `const express = require('express');` |
| ۳ | `Could not load the "sharp" module` (Termux) | ناسازگاری باینری sharp با معماری android-arm64 | جایگزینی sharp با Jimp (جاوااسکریپت خالص) |
| ۴ | `TypeError: Assignment to constant variable.` | تعریف `format` با `const` و تلاش برای تغییر مقدار آن | تبدیل `const` به `let` |
| ۵ | `FetchError: request to ... failed, reason: getaddrinfo ENOTFOUND` (tesseract.js) | نبود اینترنت در Termux برای دانلود traineddata | طراحی سیستم fallback با ocrad.js |
| ۶ | `TypeError: Jimp.read is not a function` | نصب نسخهٔ ناسازگار Jimp (ورژن ۱.x) | تثبیت نسخهٔ 0.16.13 در `package.json` |
| ۷ | `npm error 404 Not Found - tesserocr` | بستهٔ `tesserocr` در npm وجود ندارد | حذف وابستگی به آن و استفاده از tesseract.js + ocrad.js |
| ۸ | ocrad.js بدون خطا متنی برنمی‌گرداند | ارسال بافر اشتباه به Ocrad (نیاز به آبجکت شبیه ImageData) | استفاده از `pngjs` برای تبدیل بافر PNG به ساختار قابل قبول Ocrad.js |
| ۹ | کرش مرورگر هنگام OCR روی تصاویر بزرگ | پردازش سنگین در حلقه‌های تودرتو بدون محدودیت اندازه | resize تصویر به عرض ۲۰۰px و محدودیت زمان اجرا (۵ ثانیه) |
| ۱۰ | عدم امکان نصب بسته‌های سیستمی (tesseract) در Termux | خطای کلید عمومی و عدم اتصال به مخازن | روی آوردن به راه‌حل‌های کاملاً درون Node.js |

این تجربیات نشان داد که در محیط‌های constrained (مانند موبایل)، تکیه بر کتابخانه‌های کاملاً جاوااسکریپتی و ارائهٔ یک معماری fallback، کلید پایداری است.

## ۶. راه‌اندازی و نصب

### ۶.۱ پیش‌نیازها

- **Node.js** نسخهٔ ۱۸ یا بالاتر
- **npm** (معمولاً همراه Node.js نصب می‌شود)

### ۶.۲ دریافت کد

```bash
git clone https://github.com/tetrashop/tetra-shop-advanced.git
cd tetra-shop-advanced
```

۶.۳ نصب وابستگی‌ها

```bash
npm install
```

۶.۴ اجرای محلی

```bash
npm start
```

سرور روی پورت ۳۰۰۰ (یا PORT تعریف‌شده در متغیرهای محیطی) راه‌اندازی می‌شود.
پنل کاربری در آدرس http://localhost:3000 قابل مشاهده است.

۶.۵ تنظیمات اختیاری

· کلید JWT: با تنظیم JWT_SECRET می‌توان کلید امضای توکن‌ها را تغییر داد.
· توکن Hugging Face: برای استفاده از نویسندهٔ هوشمند مبتنی بر AI، متغیر HF_TOKEN را مقداردهی کنید.
· پورت: با PORT=4000 npm start می‌توان پورت را تغییر داد.

۷. استقرار روی Vercel

پروژه به‌گونه‌ای طراحی شده که بدون تغییر روی Vercel قابل اجرا باشد.

1. نصب Vercel CLI: npm i -g vercel
2. ورود: vercel login
3. استقرار: vercel

تنظیمات vercel.json به صورت زیر است:

```json
{
  "version": 2,
  "builds": [{ "src": "server.js", "use": "@vercel/node" }],
  "routes": [{ "src": "/(.*)", "dest": "server.js" }]
}
```

نکته: در Vercel، موتور Tesseract.js به دلیل دسترسی به اینترنت به‌خوبی کار می‌کند، بنابراین OCR با دقت بالا ارائه می‌شود. هم‌چنین می‌توان با تنظیم vercel-build (که در package.json موجود است) فرایند build را سفارشی کرد.

```http
  "username": "testuser",
```


۱۰. نتیجه‌گیری

پروژهٔ تترا شاپ نشان داد که با برنامه‌ریزی دقیق و انتخاب کتابخانه‌های مناسب، می‌توان یک سکوی چندسرویسهٔ پایدار حتی در محیط‌های با محدودیت منابع ایجاد کرد. چالش‌های پیش‌آمده – از ناسازگاری‌های باینری گرفته تا مشکلات اتصال – هر یک با رویکردی مهندسی حل شدند و سیستم نهایی هم به صورت محلی و هم روی cloud به خوبی عمل می‌کند. این پروژه اکنون به‌عنوان یک نقطهٔ شروع برای توسعه‌دهندگانی که به دنبال ساخت APIهای ترکیبی با قابلیت OCR و گرافیک سه‌بعدی هستند، قابل استفاده است. در آینده می‌توان با افزودن WebSocket، پایگاه دادهٔ توزیع‌شده و مدل‌های یادگیری عمیق، تترا شاپ را به یک اکوسیستم واقعاً کوانتومی تبدیل کرد.
